# CodeJr plan

CodeJr is Claude Code for the IBM PCjr. You sit at the PCjr, type "write me a snake game in BASIC", and Claude writes `SNAKE.BAS` straight onto the PCjr's own disk. Later stages compile C and assembly, test in an emulator, run on the real machine and read debug output back.

## How it fits together

```
PCjr ──serial── WiFi modem ──TCP 4860── this laptop
(MS-Kermit 3.14)                        codejr (Go binary, server/)
                                          ├─ draws the ANSI screen
                                          ├─ runs `claude -p` (Claude Code, headless,
                                          │    your subscription) in workspace/
                                          └─ sends changed files with the Kermit protocol
```

- **The PCjr runs only MS-Kermit.** No custom PCjr code until stage 5.
- **The server does everything else.** It answers the call, keeps the chat on screen, runs Claude, and pushes files.
- **`workspace/` mirrors `C:\CODEJR` on the PCjr.** Claude can only read and write there. Every file Claude changes during a turn is sent to the PCjr when the turn ends.

## Key decisions

| Decision | Choice | Why |
|---|---|---|
| Server language | Go | Compiles to one binary; good at juggling a socket, a child process and a file transfer at once. Also a language to learn. |
| Claude | `claude -p --output-format stream-json` | Your subscription, Claude Code's own tools and loop. The Agent SDK docs disallow subscription logins. |
| Claude sandbox | `--restricted --strict-mcp-config --tools Read,Write,Edit,Glob,Grep` | File tools only, confined to `workspace/`. Anyone on the LAN who connects gets this, so no shell in stage 1. |
| Port | 4860 | The PCjr's IBM machine type. |
| File transfer | Kermit protocol, written in Go | MS-Kermit already speaks it, it's error-checked, and the server owns the socket directly instead of piping C-Kermit through a pty. |
| Kermit settings | 94-byte packets, window 1, type 1 checksum, 8th-bit prefixing | The PCjr serial port has no FIFO and drops bytes, so small packets. 8th-bit prefixing keeps every byte 7-bit printable, which survives modem and telnet quirks. |
| Remote control | Kermit APC (`ESC _ command ESC \`) | MS-Kermit runs the command and returns to the terminal by itself. |

### Kermit APC facts (from KERMIT.UPD, section 10)

- APC is **OFF by default**. `SET TERMINAL APC ON` allows "safe" commands (`RECEIVE`, `SEND`, `SET`).
- `RUN` (DOS commands) needs `SET TERMINAL APC UNCHECKED`. Stage 4 needs this, stage 1 does not.
- `SET FILE COLLISION OVERWRITE` is needed, or re-sent files get renamed instead of replaced.

These settings live in `dos/CODEJR.INI`, which the PCjr launcher loads.

## PCjr side

Two files in `C:\`, generated by the server (`/setup` sends them over the line; `dos/` has copies):

- `CODEJR.BAT`: makes and enters `C:\CODEJR`, then runs `C:\MSK314\KERMIT TAKE C:\CODEJR.INI`.
- `CODEJR.INI`: the working serial settings (COM2, 9600 8N1, no flow control, full duplex, local echo off), `SET TERMINAL APC ON`, binary file type, collision overwrite, then dials the server, waits for `CONNECT`, sends Enter and connects.

The server answers `AT` commands itself (`OK`, `CONNECT`). With the real modem it never sees them; in the emulator, where the serial port is wired straight to the server, the same script works unchanged. The session starts on the first plain Enter.

One-time modem setup: `ATE0`, `ATR1`, `AT&W` (the server echoes typing; R1 makes the modem end replies with CR+LF).

## Stages

## Status (end of 2026-10-03)

This is the original plan, kept for the reasoning. For the current state and next steps read `HANDOFF.md`.

- **Stages 0 and 1 (Kermit, chat, BASIC):** done and proven on the real PCjr. BASIC means GW-BASIC: this PCjr has no BASIC cartridge.
- **Stage 2 (compilers, emulator loop):** Open Watcom and `wasm` are installed and used to build the client, the library and the games, with headless DOSBox tests. Claude on the PCjr doesn't have build or emulator tools yet.
- **Stage 3 (game library):** done as `lib/` (JRGFX), with a fast page-flipping path. Emulator-tested only.
- **Stage 4 (real-hardware feedback):** not started. Depends on the native client's run-and-report.
- **Stage 5 (native client):** became the main path. See `CLIENT.md`.

Things that turned out different from this plan: the server language stayed Go; Kermit must run in half duplex on this PCjr; the PCjr side is `C:\CODEJR.BAT`, `C:\CODEJR\CODEJR.INI` and programs in `C:\CODEJR\PROGS`; file transfer in the native client is a pull protocol, not Kermit.

### Stage 0: Plumbing
1. Install the tools (see below).
2. `codejr` answers on 4860, greets you, echoes typed lines.
3. Dial in from the PCjr, check text both ways and the echo.
4. Server sends APC `receive` and pushes `HELLO.TXT` with the Go Kermit sender. If it lands on the card, the design is proven.

### Stage 1: Chat and BASIC (first real version)
- **Screen:** 80x24, scroll region lines 1-22 for the chat, line 23 a divider, line 24 a status bar ("Claude is thinking", "Sending SNAKE.BAS 3/5 KB").
- **Input:** server-side line editor with backspace and history. `/new` starts a fresh conversation, `/files` lists the workspace, `/get NAME` pulls a file from the PCjr, `/quit` hangs up.
- **Claude turn:**
  1. Run `claude -p` in `workspace/` with the PCjr system prompt and `--resume <session>`.
  2. Stream text deltas to the screen, word-wrapped to 80 columns and converted to plain ASCII or CP437.
  3. Show tool calls on the status line ("Writing SNAKE.BAS").
  4. At the end of the turn, send every changed file over Kermit.
- **System prompt (PCjr-aware):**
  - PCjr Cartridge BASIC, ASCII `.BAS` with line numbers and CRLF.
  - 8.3 uppercase filenames, flat directory.
  - Replies short, plain text, under 80 columns, no Markdown.
  - Mention the 3-voice `PLAY`/`SOUND` and `SCREEN 5`/`6`.
- **Text files:** converted LF to CRLF on the way out. Everything is sent in binary mode so nothing else is altered.
- **Pacing:** output is throttled to the line speed (`-baud`, default 2400) so the modem buffer never overflows.
- **Tests:**
  - Go unit tests for Kermit (packet encode and decode, prefixing, checksums, lost and corrupted packets).
  - Interop test against C-Kermit over TCP.
  - End to end in DOSBox (`machine=pcjr`) running the real MS-Kermit 3.14, its serial port wired to port 4860 (`emu/`), run hidden.

### Stage 2: Compilers and an emulator loop
- NASM (`cpu 8086`) and Open Watcom C on the laptop.
- Claude gets a narrow tool for build and test:
  - The server exposes `make`-style commands to Claude via an allowlisted Bash or a small MCP server, never a free shell.
  - It runs the program hidden in DOSBox PCjr mode, captures a screenshot and `LOG.TXT`, and Claude reads both.
- `.COM`/`.EXE` and sources are both sent to the card.

### Stage 3: PCjr game library
- `PCJR.H` / `PCJR.INC` in `lib/`:
  - video modes 8 (160x200x16) and 9 (320x200x16), pixels, sprites
  - page flipping (PCjr CRT/CPU page registers), vsync
  - the SN76496 sound chip (port 0xC0): notes, noise, simple music
  - keyboard
  - `LOG.TXT` debug log
- Verified in MartyPC for cycle-accurate timing, then on the real PCjr.

### Stage 4: Real-hardware feedback
- `SET TERMINAL APC UNCHECKED` in the launcher. The server sends `run GAME.EXE`, then `send LOG.TXT`, and Claude reads the log.
- Live debug: the game writes to COM1 while running, and the server shows it to Claude. Needs `AT&D0` on the modem so it stays connected outside Kermit.
- On-demand screenshots: dump video memory over serial (16-32 KB, 1-2 min at 2400 baud).

### Stage 5 (optional)
- Native PCjr client in C: real sound, better UI, own framed protocol.

## Repo layout

```
docs/       this plan, protocol notes
server/     Go module: cmd/codejr (the server), internal/* (kermit, ansi, claude, session)
dos/        files that go on the PCjr card (launcher, Kermit settings)
emu/        DOSBox config for the emulated PCjr (MS-Kermit itself is fetched, not committed)
workspace/  Claude's working folder, mirrors C:\CODEJR (not committed)
lib/        stage 3: PCJR.H / PCJR.INC
```

## Related projects

- Nick Bild's IBM PCjr GPT-3: PCjr plus Kermit plus a Pi, chat only.
